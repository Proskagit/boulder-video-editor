## 1. Executive summary

- **Продуктовый вывод (решение владельца, 2026-10-28):**
  - ручная разметка зацепок — щелчок по зацепке, маска SAM, правка контура — остаётся основным сценарием, её качество
    устраивает;
  - автоматический подбор трассы «Авторазметка» (прежнее название «Разместить зацепки») **скрыт** из интерфейса.
    Реализация, сервисы и исследовательский код сохранены;
  - «Разметить зацепки» доступна как вспомогательный сценарий;
  - отслеживание зацепок, тайминги трассы, сдвиги и оверлеи не затрагиваются.
- **Практическая ценность автопредложений сейчас недостаточна.**
  - [Измерено] На 7 новых кадрах с независимым эталоном (пилот I1–I7) выбранный вариант нашёл 56 из 93 зацепок
    (0,60), ложных — 73 (10,4 на кадр), precision 0,43.
  - На 6 новых кадрах J1–J6 найдено 36 из 75 (0,48), ложных — 96.
  - Пользователю приходится и удалять много ложных, и добавлять пропущенные. Разметить трассу вручную с нуля зачастую
    быстрее.
- **Где теряется качество** [Диагностика]. Главные потери — не в разрешении масок и не в источнике подсказок, а в двух
  местах:
  - **(A)** цвет трассы оценивается по одной контрольной зацепке;
  - **(B)** контрольная маска SAM на объёме ложится на прикрученную зацепку.
- Ни уточнение цвета (A1 / A2), ни ранжирование графом (G2), ни YOLO, ни тайлы **не дали практически значимого
  сокращения ручной работы** на измеренных данных.
- **Итог 2026-10-28. Проверенные гипотезы не прошли установленные критерии:**
  - A1 / A2 (цвет по нескольким зацепкам): найдено +11 / +12 при нужных +17, ручная работа −1 % / +19 %;
  - B1 (флаг ошибочной контрольной маски): 0 из 3 при нужных ≥ 2. Маска объёма у SAM есть, но со score 0,04–0,20, и
    правилом D034 она не допускается.
- **Выбор альтернативной маски пользователем** (показ всех трёх контуров в режиме трассы) — единственный оставшийся
  вариант для ошибки B. Это отдельное **продуктовое решение, пока не реализуется**.
- **Когда возвращаться:** при принципиально новой гипотезе, новых данных или возможности измерить реальную экономию
  времени разметки на новых кадрах. Не возвращаться ради перенастройки порогов на уже использованных кадрах.

## 2. Текущая архитектура

Код — `src/Core/Holds/`.

1. **Клик** на кадре `T` → перенос на чистый кадр `T − 5 с` (`RouteSelection.cs`: `RouteSelectionService.PrepareAsync`,
   `RouteSelectionTransfer`, оценка движения на 960 px). Чистый кадр — в рамке 1920 × 1080.
2. **Маска контрольной зацепки** (`RouteHoldFinder.FindAsync` → `MaskAt`).
   - SAM 2.1 Large (ONNX, DirectML) на одну точку возвращает **3 маски** со score.
   - `HoldCandidateRules.Choose`:
     - допустимы маски ≤ 2 % кадра при любом score и ≤ 20 % при score ≥ 0,9;
     - берётся **наибольший score**;
     - затем крупнейшая связная компонента.
   - Контрольная принимается всегда, без проверки.
   - **В режиме трассы альтернативные маски пользователю не показываются.** Перебор альтернатив
     (`HoldMarkupViewModel.CycleAlternative`) есть только в ручной разметке.
3. **Цвет трассы** (`HoldColorSampler.Sample`).
   - Маска контрольной эродируется на 10 % радиуса; пиксели переводятся в OKLab; отбрасываются 10 % самых тёмных и
     светлых по L; берётся медиана L, a, b.
   - Это **одна точка цвета**. В ревью она не меняется: добавленные и отклонённые зацепки на неё не влияют
     (`HoldMarkupViewModel.Route.cs`).
4. **Кандидаты.**
   - Production: цветовая карта `ColorPromptPlanner` (блоки около 1/480 ширины, расстояние < 0,10, одна подсказка на
     4-связную область, не больше 300) плюс сетка D047 15 × 15.
   - На каждую подсказку — маска по тому же правилу, её цвет; подсказка внутри найденной маски пропускается; дубликаты
     сливаются по IoU ≥ 0,7.
5. **Отбор** (`RouteHoldSelector`): расстояние √((0,5 ΔL)² + Δa² + Δb²) < τ 0,08, score ≥ 0,5, фрагменты 0,8;
   ранжирование по цветовому расстоянию. τ можно менять в ревью (0,02–0,20).

**Исследовательский выбранный вариант** — не в production, тестовая копия `ResearchFindAsync` в
`tests/Vision.ModelTests/ReferenceSplitExperimentTests.cs`:
- деление крупных областей цветовой карты (> 4 × контрольной) при расстоянии 0,06, без сетки;
- порог насыщенности 0,3 × хромы контрольной;
- **V1** — плюс ограничение оттенка \|Δh\| ≤ 30° при C ≥ 0,025.

## 7. Открытые гипотезы

1. **Цвет по нескольким подтверждённым зацепкам** [Гипотеза].
   - Офлайн A1 показал выигрыш только на кадрах типа A (J5 2 → 6, I7 4 → 6), но в сумме не сократил ручную работу.
   - Нерассмотренный вариант — **A3**: цвет обновляется по зацепкам, которые **пользователь сам подтвердил** в ревью.
     Это изменение интерфейса, решение владельца.
   - Офлайн честно не моделируется: нет данных о действиях пользователя.
2. **Выбор контрольной маски из альтернатив SAM** [Гипотеза]. Признаки ошибки:
   - выбранная маска вложена в другую допустимую маску (отношение площадей ≥ 3);
   - она контрастна к её кольцу (расстояние ≥ τ).

   Предварительно лучше **показать альтернативы или флаг пользователю (B1)**, чем выбирать большую автоматически (B2):
   пользователь мог иметь в виду прикрученную зацепку.
3. **Цвето-независимый пул + исправимый цвет** [Потолок]. С пулом YOLO потолок выше (53 против 44 на J1–J6), но только
   при верном цвете. Имеет смысл лишь после того, как решены 1–2.
4. **Фильтр меток и посторонних объектов** (форма, размер, положение) — не исследовался.
