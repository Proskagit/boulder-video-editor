## 3. Independent check of the source set (plan)

What exists: the second CI build ran only from the fetched sources (checked against `SHA256SUMS`, no network) and gave
the same bytes. What is missing: a rebuild from the published tar alone, with the toolchain image rebuilt from scratch.

1. **A separate job or machine**, not reusing anything from run `39738528058`: a fresh GitHub-hosted runner of another
   image (e.g. `ubuntu-22.04` against the original `ubuntu-24.04`), or a Linux machine with Docker.
2. Download **only** `aive-ffmpeg-minimal-9.0.2-sources.tar`; check its SHA-256 against the release's `SHA256SUMS`.
3. Extract; check every file against the tar's own `SHA256SUMS`.
4. Build the toolchain image from `recipe/Dockerfile` with `--no-cache --pull` (the base image by digest, the packages
   from the snapshot); compare its `dpkg-query` list with `toolchainPackages` in `manifest.json`.
5. Run `recipe/build.sh` with `--network=none`, the extracted folder as `/sources` (read-only).
6. Compare `ffmpeg.exe` / `ffprobe.exe` with the published SHA-256. Equal: the source set is sufficient and the build
   reproducible across hosts. Different: compare `ffmpeg-configuration.txt`, `enabled-config.txt` and the toolchain list
   to find the cause; no publication until explained.
7. Optional: unpack the Debian source packages (`dpkg-source -x`) to show they are complete and match their `.dsc`
   checksums; rebuilding the toolchain itself from them is not planned (whether that is needed is part of the legal
   review).

Effort: one CI job (about 15 minutes) or one manual run. It needs the product owner's permission (a workflow change on
`build/ffmpeg-minimal`, or a manual run elsewhere).

## 4. Release notes (draft)

> **Minimal FFmpeg 9.0.2 for AiVideoEditor — build 1 (win64)**
>
> The FFmpeg build AiVideoEditor's portable version is to ship (not yet part of any AiVideoEditor release).
> FFmpeg 9.0.2 with only what the editor uses: decoding H.264, HEVC, MPEG-4 Part 2, MJPEG, VP8, VP9, AV1 (dav1d), AAC,
> MP3, PCM, FLAC, Opus, Vorbis, ALAC, PNG, JPEG, WebP, BMP from MP4 / MOV / M4A, MKV / WebM, AVI, WAV, MP3, FLAC, ADTS;
> encoding H.264 (x264) and AAC into MP4; the editor's filters (incl. `zscale`, `lut3d`); d3d11va / dxva2 decoding.
> No network, no other external libraries.
>
> - `ffmpeg.exe` 17 416 704 bytes, SHA-256 `9f51787f…3610`; `ffprobe.exe` 17 206 784 bytes, SHA-256 `2a1bf15f…5ab3`.
> - Built in a pinned Debian container (digest, snapshot 20261020T000000Z) without network, twice, byte-identical
>   (run 39738528058); recipe: `tools/ffmpeg-minimal` at `9a3afd6`.
> - Licence: GPL version 2 or later (FFmpeg with x264); see `THIRD-PARTY-NOTICES.txt`. Complete corresponding source:
>   `aive-ffmpeg-minimal-9.0.2-sources.tar`; see `SOURCE-OFFER.txt`.
> - Checked on Windows against gyan.dev 9.0.1: decoding, the HDR graph and the H.264 export identical; the AAC export
>   stream and the raw ADTS decode differ slightly (FFmpeg 9.0.2's encoder; float rounding). Hardware AV1 not checked on
>   CI (no GPU).
> - Patents: the codecs may be covered by patents in some countries; no patent licence is granted.
