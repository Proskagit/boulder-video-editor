# Phase 23 — manual test plan

Manual checks of the direct Move, Scale (corner handles) and Crop in the Preview (DECISIONS.md D038). Run in the real app on
Windows. Fixture: `tools/manual/New-Phase23TransformFixture.ps1` — canvas 1920 × 1080, 25 fps: a 2 × 2 composition of four
videos on V1–V4 (each at 50 % in its quarter, 0–8 s), a portrait (phone) clip stored landscape with a 90° display rotation
and a text "TITLE" (10–18 s), a clip rotated by 30° at 60 % and an image (20–28 s), a clip on the locked V5 (30–38 s); for
row 22 the same project with the canvas set to 1080 × 1920 in `project.json`.

Run on 2026-10-19 by Claude on Windows 11, the Debug build of `8c34f65` + the fixes of `99b3118` (found in this run, below),
driven by system mouse / keyboard input and UI Automation; results read from the Inspector's fields (UI Automation),
the status bar, the window title, the saved `project.json`, the exported file and screenshots. Not isolated: the app writes
its logs, recovery files and the recent-projects list under the real `%LOCALAPPDATA%\AiVideoEditor`.

Found in this run and fixed (`99b3118`): (1) a frame scaled or moved past the canvas was drawn over the panels around the
Preview (the top bar, the Media Browser) — the overlay now clips to its bounds; (2) the corner handles of a clip that fills
the canvas lay on the overlay's edge, half cut off, and a press exactly on the corner missed — the overlay now reaches over
the Preview's 16 px margin (`PreviewTransformOverlay.Inset`) with the canvas mapped exactly as before. Rows 3–24 were
(re)checked on the fixed build.

- **auto** — covered by automated tests only, not checked in the real app;
